# 复用指南

本扩展与 Mattermost 产品强耦合（登录、消息接口、频道模型、WebSocket 事件协议）。
复用时必须区分「**测试方法可以迁移**」和「**代码可以直接运行**」。

## 复用决策表

| 后续被测系统 | 复用方式 | 适配量 |
|---|---|---|
| 当前项目的新版本 / 新环境 | 改参数（地址、账号文件、频道 ID、发送比例）后直接复用，先做冒烟回归 | 极小 |
| 其他 Mattermost 部署 | 核对版本号、鉴权方式（token/MFA/LDAP）、团队/频道模型差异后复用 | 小 |
| 基于 Mattermost 二次开发的系统 | 按接口与 WS 事件兼容程度决定：登录/发帖 API 兼容则大部分可复用 | 中 |
| 其他开源 IM（Rocket.Chat / Zulip / Matrix 等） | **不能**因为都是开源或都用 WebSocket 就直接复用；登录、消息接口、会话模型、事件协议全部需要适配层重写 | 大 |
| 自研 IM / 商业 IM | 压力模型、就绪门控、指标体系、监控与核账方法可以迁移；通信实现需重新开发 | 大（仅方法论复用） |

## 跨环境复用检查单

换环境时按顺序核对，全部打勾后再跑正式压测：

**1. 连接与鉴权**
- [ ] `ServerURL` / `WebSocketURL` 可达（`curl /api/v4/system/ping` 返回 200）
- [ ] 管理员凭据有效且具备 system_admin 权限
- [ ] 如有 MFA / SSO / LDAP，先确认绕过或专用测试账号方案

**2. 数据准备**
- [ ] 用 `scripts/mattermost_prepare_users.py` 预置用户，用户名前缀 + 数字序号规则与 `--user-prefix` 一致
- [ ] 用 `scripts/mattermost_assign_users.py` 完成团队/频道分配（频道群发场景还需要目标频道 ID）
- [ ] 凭据文件权限 `chmod 600`，且**不要提交到 git**

**3. 参数适配**
- [ ] `LT_GROUP_SIZE` 与实际可用用户数匹配（用户数应整除组大小，余数用户会报错）
- [ ] 单聊场景用户数为偶数；群聊场景用户数为 `LT_GROUP_SIZE` 的整数倍
- [ ] `MaxActiveUsers` ≥ 实际 `-n` 参数
- [ ] 登录治理参数（`LT_LOGIN_CONCURRENCY` 等）按被测端登录接口承受能力设定

**4. 基线验证（最小复现实验）**
- [ ] 按 README「最小复现」跑通 登录 → 单聊 → 群聊 冒烟
- [ ] 指标端点 `/metrics` 有数据，`loadtest_websocket_events_received_total` 持续增长
- [ ] 延迟文件有数据，P95 在可解释范围内
- [ ] 冒烟通过后再上量

## 版本升级回归策略

被测 Mattermost 升级后：

1. 先跑最小复现冒烟（登录/单聊/群聊），确认 API 与 WS 事件协议未变；
2. 重点核对：`/api/v4/posts`、`/api/v4/channels/direct`、`/api/v4/channels/group`、`GetUsersByUsernames`、`posted` 事件数据结构；
3. 若上游 load-test-ng 发布了适配新版本的更新，评估 rebase 本扩展改造点（改造集中在 9 个文件，见 `EXT-CHANGES.md`，冲突面可控）。

## 方法论迁移清单（适用于任何 IM）

即使代码无法复用，以下设计可以直接搬到新工具：

- **确定性配对/分组模型**：用户名编号 → 配对关系纯函数推导，免除运行时发现开销，流量模型可精确预期；
- **时间戳随消息体传递 + 接收侧解析**：不依赖时钟同步服务之外的任何设施，即可获得端到端延迟；
- **就绪门控**：在线数与 WS 连接数双达标才开始计时，杜绝"预热期数据污染稳态结论"；
- **收发分离部署**：发送者与接收者可以是不同进程/机器，通过开始信号文件对齐计时起点；
- **凭据与配置外置**：所有环境差异收敛到配置文件与环境变量，代码零硬编码；
- **核账方法**：发送计数（客户端日志）= 接收计数（WS 事件）= 服务端落库计数（DB 抽查），三方对账。
